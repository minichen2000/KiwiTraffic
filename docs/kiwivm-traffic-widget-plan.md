# KiwiVM 流量桌面小工具功能介绍与实施计划

版本：1.0  
日期：2026-10-07  
面向：负责实现、测试与交付的 Coding Agent  
状态：开发规格已整理；真实 API 数据契约尚待核实，尚未开始实现。

本项目为搬瓦工 KiwiVM 用户提供一个 Windows 桌面常驻工具，让用户随时看见 VPS 当前套餐流量周期的已用百分比、剩余流量和下次重置时间。采用 C#、WPF 与 .NET，交付绿色版 EXE。第一版只监控单台 VPS，直接从 Windows 查询官方 API，不需要在 VPS 安装程序。

本文件可独立交给其他 Coding Agent 使用。文件内的默认行为属于实现要求；标记为“待核实”的 API 名称、字段和语义不能当成已确认事实。当前用户请求是编写本计划；拿到后续开发授权再执行编码、安装依赖或仓库初始化。

## 1 产品目标与范围

### 1.1 核心使用场景

用户日常使用电脑时，不必打开 KiwiVM 面板，就能一眼看到当前流量用量。用户也能快速判断剩余流量是否够用、何时重置，以及画面上的数据是否仍然有效。

第一版必须做到：

- 以大字号显示本周期已用百分比。
- 显示已用量、总额度、剩余量和下次重置时间。
- 通过小悬浮窗和系统托盘常驻，支持拖动、置顶和记住位置。
- 自动刷新和手动刷新，并显示最近一次成功取得数据的时间。
- 对流量阈值给出不重复打扰的提醒。
- 在断网、限频、密钥失效等情况下准确说明状态，不把错误伪装成零用量。
- API Key 在本机输入、加密保存，不进入代码仓库或日志。

### 1.2 第一版不包含

- VPS 启停、重装、迁移、快照、重置密钥等管理操作。
- 多 VPS 聚合、账号同步、移动端、网页管理后台。
- 实时网速、CPU、内存、SSH 监控。
- 历史流量曲线、每日用量统计和周期结束用量预测。
- 自动更新器、安装包、商业代码签名和公开发布。

后续可增加上述监控扩展，但不能为了预留扩展而引入数据库、后端服务或复杂插件系统。

## 2 技术选型与运行条件

| 项目 | 要求 |
| --- | --- |
| 运行平台 | Windows x64；目标 Windows 10/11，最终支持的系统版本需与所选 .NET 官方支持范围核对并记录 |
| 编程语言 | C# |
| 桌面界面 | WPF，轻量 MVVM 分层 |
| 托盘 | Windows Forms 的 NotifyIcon，与 WPF 配合使用 |
| 运行时 | 实施时仍受官方支持的 .NET LTS；在 M1 固定 SDK 与目标框架，写入 global.json 和构建文档 |
| 网络 | HttpClient，异步请求、取消、超时、可控代理 |
| JSON | System.Text.Json，显式校验字段与业务状态 |
| 密钥保存 | Windows DPAPI，CurrentUser 范围 |

“绿色单文件”指分发一个 EXE、无需安装器，不承诺运行时零落盘。.NET 单文件可能解压内部原生组件；设置与凭据保存在当前用户目录。不要为了减小体积直接启用未经验证的 WPF trimming 或 Native AOT。

默认用系统自带字体和简单矢量图标，不要求联网下载字体或图标资源。运行过程中无需管理员权限。

## 3 官方 API 事实与核实清单

### 3.1 已确认事实

用户提供的 KiwiVM 官方 API 页面截图确认：

- API 使用 VEID 和 API Key。
- 支持通过 GET 或 POST 传递参数。
- 示例查询入口是 `https://api.64clouds.com/v1/getServiceInfo`。
- 请求参数名为 `veid` 和 `api_key`。

官方服务介绍确认 API 文档与示例位于 KiwiVM 面板内。当前没有取得完整官方字段说明，也没有使用真实密钥调用接口。

已有用户 VEID 可由用户在首次配置时填写；不要将真实 VEID、IP、主机名或账户信息写死在程序、测试样本或公共文档中。

### 3.2 实施前必须核实的数据契约

下表的字段和补充接口仅是待核查候选，不得照表直接假定实现正确。

| 候选内容 | 必须核实的问题 |
| --- | --- |
| getServiceInfo | 是否直接包含完整的本周期流量信息，是否有套餐或虚拟化类型差异 |
| data_counter | 是否为本周期已用量；单位、计费口径、合法数值范围 |
| plan_monthly_data | 是否为本周期总额度；单位；缺失、零值或特殊额度的含义 |
| data_next_reset | 含义、时间格式、时区与更新时间；是否为 Unix 秒级时间戳 |
| monthly_data_multiplier | 是否存在，如何作用于已用量和额度；接口是否已应用倍率 |
| API 业务错误字段 | 成功判定、认证错误、限频错误及其他业务错误如何表示 |
| 调用频率 | 是否有官方限频说明、响应头或 getRateLimitStatus 等查询能力 |
| getLiveServiceInfo | 仅在 getServiceInfo 无法满足需求时评估；确认成本及限制 |
| 密钥权限 | 是否支持只读密钥或权限限制；未确认前按高权限凭据保护 |

还需确认入站和出站如何计费、VPS 关机时是否仍能查询，以及迁移等情况下计数器是否有特殊规则。任何无法验证的行为都应留在 PROGRESS.md，不得自行编造。

### 3.3 核实方法与阻塞边界

1. 请用户复制 API 页中相关接口的字段和错误说明，无需提供 API Key。
2. 记录出处、核实日期和必要的短摘录到 `docs/api-contract.md`，只摘录实现所需信息。
3. 在程序具备本地配置界面后，由用户自行输入密钥进行查询。
4. 核对程序与 KiwiVM 面板的已用量、额度、百分比和重置时间，记录采样时间差。
5. 测试样本优先使用根据已确认契约构造的合成数据；如采用真实响应，先去除全部身份信息和凭据。

未取得契约时，可继续完成架构、模拟数据、界面和测试基础设施；模拟模式必须明确标识。真实流量换算、周期通知和账号联调不能据此宣称完成。不要要求用户为了开发把密钥发送到聊天中。

## 4 功能与交互要求

### 4.1 首次配置

首次启动无配置时打开设置窗口，引导填写 VPS 别名、VEID 和 API Key。别名可选，VEID 必须为合法正整数，密钥不能为空。

密钥默认遮蔽，可通过用户操作临时显示。提供“测试连接”“保存”“取消”。网络连接失败不能抹去当前有效配置。编辑现有配置时，在保存成功后再切换运行中的账号；取消编辑应保留原状态。

默认设置：

| 设置 | 默认值 |
| --- | --- |
| 自动刷新间隔 | 5 分钟；候选选项为 5、10、15、30、60 分钟，最终不得违反官方限制 |
| 开机启动 | 关闭，用户主动启用 |
| 窗口置顶 | 开启，可关闭 |
| 首次显示位置 | 主显示器工作区右下角，避开任务栏 |
| 流量提醒 | 开启，80%、90%、95% |
| 代理 | 系统默认，可切换直连或手动 HTTP 代理 |
| 界面语言 | 简体中文 |

“系统默认代理”应准确说明 .NET 的代理解析方式，不能承诺它与某个浏览器扩展的代理一致。手动代理支持主机和端口；如支持代理密码，必须与 API Key 一样加密，禁止明文写入代理 URL。第一版不承诺 PAC 编辑或 SOCKS 支持。

### 4.2 桌面悬浮窗

参考初始尺寸约为 280 × 150 DIP；以内容完整显示为准，不能为了固定尺寸截断重要信息。

显示层级：

1. VPS 别名和简洁状态标识。
2. 已用百分比，保留一位小数，大字号。
3. 进度条，以及“已用 / 总额度”。
4. 剩余流量、重置倒计时；完整重置时间可通过悬停或详情查看。
5. 最近成功更新时间；失败时显示简短错误状态。

颜色默认规则：低于 80% 为正常色，80% 至不足 90% 为警示色，90% 及以上为高用量色。颜色只是辅助，必须同时保留数字和文本。

支持拖动、置顶切换、隐藏到托盘、打开设置和手动刷新。点击关闭只隐藏窗口；首次执行时提示程序仍在托盘运行。托盘菜单必须有明确的“退出”。

窗口位置以 DPI 正确的方式保存。重启、显示器断开、分辨率或缩放变化后，必须确保窗口可见且落在某个屏幕工作区。托盘提供“恢复窗口位置”作为补救。

### 4.3 托盘与程序生命周期

- 托盘提示显示别名、百分比和状态；遵守系统提示长度限制。
- 托盘菜单包含显示／隐藏、刷新、置顶、设置、恢复位置和退出。
- 程序采用当前用户范围的单实例机制，重复启动时唤起已有窗口。
- 主窗口隐藏后仍正常刷新；退出时取消请求、清理 NotifyIcon 并释放资源。
- 开机启动使用当前用户级机制，不提升权限；取消勾选时清除本工具的启动项。
- EXE 移动后应允许修复开机启动路径；不得承诺旧路径会自动跟随移动。

### 4.4 提醒

仅依据成功取得且校验通过的新数据判断提醒，不依据缓存反复提醒。

同一账号、同一已确认周期内，每个阈值最多提醒一次。一次采样越过多个阈值时，只提醒最高阈值，并将较低阈值一并记为已覆盖。首次联网已高于阈值时，也只提醒最高阈值一次。

提醒记录持久化，重启后不重复轰炸。周期标识必须依据已核实的 API 周期语义生成；不能仅凭本地日期变化或计数器下降就判断进入新周期。无法确定周期时，暂停自动周期提醒，并在设置中说明原因，仍可显示有效流量数据。

第一版可使用托盘通知，不为通知单独引入安装器。系统专注模式或通知设置可能抑制提示，因此窗口和托盘状态也必须反映高用量。

## 5 流量计算与数据显示

所有换算集中在一个独立的映射／计算模块中。UI 不得直接读取原始字段或自行处理倍率。

在 M0 核实单位与倍率规则后，将响应转换为同一口径的已用字节数和额度字节数：

```text
usedPercent = usedBytes / quotaBytes × 100
remainingBytes = max(quotaBytes - usedBytes, 0)
progressBarValue = clamp(usedPercent, 0, 100)
```

- 原始计数与中间计算使用足够精度的数值类型，建议 decimal；避免整数除法和提前舍入。
- 百分比文字不截断到 100%；例如真实为 103.2%，应显示 103.2%，仅进度条封顶。
- 阈值比较使用未舍入的百分比。
- 总额度为零、负值、缺失或无法解析时，不进行除法，显示“额度未知”或契约定义的特殊状态；不得推断为无限流量。
- 已用量为负值、字段溢出或响应不合法时，不替换最近一次有效快照。
- 基于字段契约进行解析，不擅自把任意数值字符串当作合法数据。
- 单位必须标清：GB 使用十进制，GiB 使用二进制。最终展示口径与面板核对；不可把 GiB 标为 GB。
- 倍率处理只做一次。只有确认分子与分母使用同一倍率，才允许利用比例抵消；剩余量仍需正确换算。
- 重置时间以服务商返回值为准，不假设每月一日，也不假设周期固定 30 天。
- 内部使用 DateTimeOffset 和 UTC，展示使用 Windows 当前用户时区，完整时间显示时区或偏移。
- 重置字段缺失时显示“重置时间未知”；已过期时显示“待服务商更新”，不得自行把流量归零。

百分比与面板的验收应考虑同一时间段的新增流量及显示舍入。对同一份输入数据，按约定公式得到的结果必须精确符合测试预期；不能用“大致接近”掩盖单位或倍率错误。

## 6 网络调度与异常状态

### 6.1 请求要求

- 默认使用 HTTPS POST 表单提交参数，避免密钥进入查询 URL。
- API 主机与路径采用官方验证后的固定允许列表；第一版不开放任意 API Base URL。
- 不关闭 TLS 证书校验；不允许把含密钥的请求自动重定向到其他目标。
- 同一时间最多一个查询请求。手动刷新、定时刷新和唤醒刷新使用同一个协调器。
- 请求超时初定 20 秒，最终按已确认接口的行为调整。
- HTTP 成功不等于业务成功，必须检查 API 业务错误以及字段有效性。
- 切换账号、修改密钥或退出时取消旧请求；即使取消后旧请求仍返回，也不得覆盖新配置的数据。
- 支持取消，不在 UI 线程阻塞等待网络或同步写入大量数据。

### 6.2 刷新策略

- 启动后读取缓存并标明缓存时间；配置有效时发起一次查询，遵守已持久化的限频冷却期限。
- 正常状态按用户间隔查询；单次完成后再安排下一次，避免重叠。
- 临时网络错误采用退避，例如 5、10、20、40、60 分钟，上限 60 分钟，可加小幅抖动。
- 服务端给出的冷却／重试时间优先；这些示例不是官方限频数值。
- 手动刷新也遵守官方限制和限频冷却；本地防连点间隔初定 30 秒。
- 系统睡眠期间不累计补发请求；恢复时合并为一次必要刷新，受同一频率约束。
- 认证或权限错误停止自动重试，提示修改配置；修复后通过测试连接或手动刷新恢复。
- 不额外轮询高成本实时接口，除非 M0 证明它不可替代。

### 6.3 状态模型

| 状态 | 画面行为 |
| --- | --- |
| 未配置 | 引导设置，不显示假用量 |
| 加载中且无缓存 | 显示加载状态，占位符不是 0% |
| 更新中且有数据 | 保留旧数据，显示更新中 |
| 正常 | 展示数据与成功更新时间 |
| 离线／超时 | 保留旧数据，显示失败原因和旧数据时间 |
| 限频 | 保留旧数据，显示可重试时间 |
| 密钥或权限错误 | 保留同账号旧数据并标记不可更新，引导设置 |
| 返回值无效 | 不覆盖有效缓存，显示数据异常 |
| 缓存过期 | 明确标识旧数据，禁止表现为刚刚更新 |

初定超过两个配置刷新间隔未成功更新即标记“数据过期”；失败一发生就显示更新失败，不必等到过期。相对更新时间必须随时间变化，不能永久停留在“刚刚”。

## 7 凭据 配置与缓存

建议应用内部名为 `KiwiTraffic`，仅作默认代码与目录名，不表示已创建远端仓库。普通配置放在 `%LOCALAPPDATA%/KiwiTraffic/`。

建议文件：

| 文件 | 内容 |
| --- | --- |
| settings.json | schemaVersion、别名、VEID、代理模式、刷新间隔、窗口位置、提醒设置 |
| credentials.dat | DPAPI 加密后的 API Key，以及存在时的代理凭据 |
| cache.json | 最近有效的归一化快照、采样时间与所属配置标识 |
| notifications.json | 当前确认周期与已触发阈值 |
| logs/ | 有限大小的脱敏诊断日志，自动轮转 |

要求：

- API Key 不保存为明文，不放环境变量示例的真实值，不进入命令行、异常、遥测或剪贴板自动操作。
- 日志不得记录请求体、认证信息、完整原始响应或密钥的任何可恢复片段。
- 默认不做云同步或遥测。数据仅在本机处理。
- DPAPI 使用 CurrentUser；换用户或换电脑无法解密时，引导重新输入，保留可读取的普通设置。
- “记住密钥”可默认启用；用户应能删除本机保存的凭据。
- 文本文件按 UTF-8 无 BOM 写入，使用临时文件与原子替换；读取时容忍 UTF-8 BOM。
- 配置损坏先保留备份，再提示恢复；不得静默用默认值覆盖原内容。
- 配置、缓存、提醒记录带 schemaVersion，升级时执行明确迁移。
- 缓存必须绑定账号／VEID与配置标识，切换 VPS 后不得显示上一台数据。
- 保存配置与加密凭据时处理部分失败，避免新配置意外使用旧密钥；多文件可通过版本标识和安全写入顺序保持一致。
- 发布前检查源码、测试样本、构建产物目录及日志，不得包含用户真实凭据。

绿色 EXE 不等于密钥可随 EXE 跨电脑携带。README 应说明数据目录、清除数据和关闭开机启动的方法。

- `UsageCalculator`：纯计算与有效性校验。
- `RefreshCoordinator`：统一调度、互斥、取消、退避和配置切换。
- `ICredentialStore`、`ISettingsStore`、`IUsageCache`：分别处理凭据、配置、缓存。
- `NotificationPolicy`：按账号、周期和阈值去重。
- `WidgetViewModel`：将状态转换为显示文本，不直接请求 API。

建议快照字段为 `ProfileId`、`Veid`、`UsedBytes`、`QuotaBytes`、`NextResetAtUtc`、`FetchedAtUtc`。未知字段用显式空值／状态表达，不能用 0 兼任“未知”。只有验证成功的响应才更新成功时间。

## 9 构建与交付要求

以下是 Coding Agent 需要实现的命令，不是当前已可用命令：

| 命令 | 目标 |
| --- | --- |
| dotnet test | 执行自动化测试 |
| npm run build:exe | 日常 fast 档，生成可运行的绿色 EXE |
| npm run build:release | 正式 Release 档，执行质量检查并生成发布 EXE |

`package.json` 仅作用户习惯的命令薄封装，不引入前端框架和不必要的 npm 依赖。脚本使用 pwsh 7，也提供直接调用方式，使 .NET 开发者可以不安装 Node.js。

两档均通过 .NET 发布配置生成 Windows x64 自包含单文件。fast 优先快速反馈，避免昂贵优化；release 使用正式 Release 配置，并验证最终产物。不要将 Rust 的 LTO 或 cargo 参数照搬到 .NET。

关键发布属性至少核查 `SelfContained`、`PublishSingleFile` 和 `IncludeNativeLibrariesForSelfExtract`。建议产物位于 `dist/fast/` 和 `dist/release/`；外部调试符号可保留在构建目录，但交给用户的必需运行文件应为一个 EXE。禁止默认生成 MSI、MSIX 或 NSIS 安装包。

版本选择、restore、构建、测试和清理命令写入 BUILD 文档。显式声明依赖、固定必要版本并提交适用的锁文件；不要依赖开发机器碰巧全局安装的包。

首次大规模下载前检查网络与依赖源。npm 如需下载依赖按用户镜像约定处理；NuGet 先检查官方源和代理，不凭空套用其他生态镜像。修改用户级配置前告知用户，镜像设置不写进仓库，境外 CI 不使用国内镜像。

本地构建 release 档不等于发布版本。创建远端、推送、打 tag、上传发布产物需有对应的用户授权；有远端时命名使用 `github` 和 `gitee`。未来如要求正式发版，采用 tag 触发 GitHub Actions 云端构建与发布，并复用本地构建脚本。

## 10 分阶段实施计划

### M0 核实 API 与运行环境

工作：获取官方相关字段说明，填写 `docs/api-contract.md`；确认单位、倍率、周期、错误格式和限频；确认目标电脑 Windows 架构与可用 SDK。

交付：API 契约表、合成响应样本、未决项列表、SDK／目标框架选择。

完成条件：关键流量字段可唯一映射到领域模型；未确认的接口差异被明确列出。若用户暂未提供文档，可先推进不依赖真实接口的 M1 和 M3，M2 的真实适配不得标记完成。

### M1 建立骨架与纯计算模块

工作：创建解决方案、分层项目、测试项目、核心模型、计算与校验函数、状态模型、构建脚本基础和模拟模式。

交付：可编译项目与计算测试；README 明确当前处于开发中。

完成条件：正常、零额度、超额、异常值和精度边界测试通过；模拟界面能展示明确标识的测试数据。

### M2 完成凭据配置与真实 API 适配

工作：配置窗口、DPAPI、HTTP POST、业务错误处理、代理、契约映射、连接测试、缓存和配置切换取消逻辑。

交付：用户可以在本机输入密钥的程序，以及无凭据的自动化测试。

完成条件：合成契约测试通过；真实账号数据与面板完成首次对照。真实账号暂不可用时，保留“待联调”状态，不得宣称真实接口验收通过。

### M3 完成悬浮窗与托盘

工作：按第 4 节实现布局、显示状态、拖动、置顶、隐藏、菜单、单实例和窗口位置恢复。

交付：日常可运行的 fast 版 EXE。

完成条件：用户能够从托盘找回窗口；窗口关闭不退出，菜单退出能释放程序；高 DPI 下内容不截断，断开显示器后窗口不丢失。

### M4 完成刷新 提醒与恢复机制

工作：自动刷新、手动节流、失败退避、限频冷却、睡眠恢复、旧数据提示、阈值去重和可选开机启动。

交付：可长期常驻使用的候选版本。

完成条件：重复操作不产生并发请求；失败不清空有效数据；配置切换不串数据；提醒不会因重启或一次跨越多个阈值而重复刷屏。

### M5 验收 文档与绿色产物

工作：执行第 11 节验收，修复缺陷，核对发布产物依赖，更新全部相关记录，记录实测启动时间、内存与 EXE 体积。

交付：绿色 EXE、版本及 SHA-256、构建说明、使用说明、测试结论和已知限制。

完成条件：所有必须项通过；无法实测的事项明确列为未验证。仅模拟通过不能满足真实流量正确性验收。

每个里程碑完成后更新 PROGRESS.md；接口核实结果只在 `docs/api-contract.md` 展开，进度文件放摘要和链接，避免多处重复维护同一事实。

## 11 验收与测试矩阵

| 场景 | 预期结果 | 验证方式 |
| --- | --- | --- |
| 已用 250、总量 1000，同单位 | 25.0%，剩余 750 | 纯计算测试 |
| 已用超过总量 | 文字大于 100%，进度条封顶，剩余为 0 | 纯计算测试 |
| 额度为零／缺失，计数负值或溢出 | 明确异常或未知状态，无除零、崩溃或假 0% | 契约与计算测试 |
| 百分比接近 80% 等阈值 | 按未舍入数值判断提醒 | 通知策略测试 |
| 大计数器与倍率 | 精度和单位正确，无重复乘倍率 | 已确认契约样本测试 |
| 重置时间缺失或已过期 | 显示未知或等待更新，不自动清空用量 | 固定时钟测试 |
| HTTP 200 但业务失败 | 不当成查询成功，不更新成功时间 | 假 HTTP handler |
| 超时、网络错误、损坏 JSON | 保留旧快照，明确错误状态 | 假 HTTP handler |
| 限频与服务端冷却 | 自动和手动刷新都遵守期限 | 假 HTTP handler 与时钟 |
| 同时触发多个刷新 | 实际最多一个请求 | 调度并发测试 |
| 请求途中切换账号 | 旧响应不能覆盖新账号数据 | 受控异步测试 |
| 一次采样跨越 80%、90%、95% | 只发送最高已跨越阈值的单条提醒 | 通知策略测试 |
| 重启或重复收到同一周期响应 | 已触发阈值不重复通知 | 持久化测试 |
| 配置损坏／DPAPI 解密失败 | 保留原文件或备份，引导恢复 | 临时目录与 Windows 测试 |
| 隐藏主窗口、重复启动、退出 | 托盘可找回，单实例，无残留后台进程 | 本机人工验收 |
| 不同 DPI、多显示器断开 | 内容完整，窗口仍可见 | 可用设备人工验收 |
| 睡眠后恢复／网络恢复 | 合并刷新，无请求风暴 | 本机验收与调度测试 |
| API Key 修改、缓存账号不匹配 | 无旧凭据串用或跨账号显示 | 配置切换测试 |
| 实际用量与 KiwiVM 对照 | 百分比、额度、单位、重置时间一致，记录采样差异 | 用户本机联调 |
| 无单独 .NET 安装的目标环境 | EXE 正常启动，无运行时安装提示 | 可用干净 Windows 环境验证 |
| 日志与版本控制检查 | 无真实密钥、原始敏感响应和用户配置 | 脱敏与产物检查 |

桌面／浏览器 UI 自动化必须先说明用途并获得用户本次明确同意。默认通过代码、CLI、可替换接口和自动化测试完成验证；需要人工观察的场景提供步骤和预期结果，不把未执行的 UI 场景写成已通过。不得为测试错误密钥、限频或周期重置而高频请求真实服务。

无需为纯布局细节编写机械快照测试。自动化测试应集中保护计费正确性、异常恢复、凭据隔离和并发行为。

## 12 Coding Agent 工作约定与交接

开始实施时依次读取目标仓库的 AGENTS.md、PROGRESS.md、已有 README／BUILD 和本计划；如果文件不存在，在初始化阶段建立。已有仓库有额外约束时先协调，避免覆盖用户工作。

- 按里程碑推进，不把本文件描述的目标写成已经完成的功能。
- 缺少密钥不妨碍实现模拟界面和自动化测试；缺少契约不允许猜测真实流量口径。
- 常规技术细节按本计划自主落实；只对实质影响正确性、范围或外部副作用的缺失信息求证。
- 联网调研、大输出排查和长任务优先后台或子代理执行，主对话只带回结论和关键错误。
- Windows shell 使用 pwsh 7；编辑文本使用 agent 的 edit／write 工具，不用 PowerShell Set-Content、Out-File 或重定向做文本往返。
- 不对 VPS 执行管理操作，不读取无关账户凭据，不开启未要求的遥测。
- 不将本次计划编写视为创建远端、推送或发布的授权。
- PROGRESS.md 用中文记录进度、待办、实测与一次性排查；CHANGELOG.md 用英文记录用户可见变化到 Unreleased。
- README.md／README.zh.md 记录功能与用法；BUILD.md／BUILD.zh.md 记录已验证的构建、测试与发布命令。
- AGENTS.md 只沉淀长期有效的技术栈、命令、目录和禁令，正文不复制整份计划；放一行指向本计划。

最终交付报告必须明确：产物绝对路径、版本、运行方式、配置方法、真实 API 是否联调通过、已执行的测试、未验证环境，以及尚未解决的限制。不得用“功能已完成”掩盖真实账号尚未对照的状态。

## 13 用户配合项

当前首先需要用户提供 API 页中相关字段与错误说明，不含密钥。取得说明后，Coding Agent 应能自行推进大部分开发。

真实联调阶段需要用户：

1. 在本机程序中输入 VEID 和 API Key。
2. 对照 KiwiVM 面板的流量信息，确认单位、比例和重置日期。
3. 如当前网络无法访问 API，确认可用代理配置；无需提供代理账户秘密到聊天中。

界面默认采用本计划方案，不把窗口颜色、位置等可后改细节作为开工阻塞项。
